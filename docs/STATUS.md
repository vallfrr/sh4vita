## What works

- Static recompilation of the whole exe (9,462 guest functions -> C), x87 stack mapped to locals statically (2,743 static functions, 41 dynamic).
- D3D8 emulated on vitaGL/GLES2: fixed pipeline and vs/ps 1.x translated to GLSL (compiled with Sony's `libshacccg.suprx`), shader cache at `ux0:data/sh4/shc`.
- Threads: game logic on core 0, GL render thread on core 1 (`qgl.c`), D3D8 prep thread + async log + audio on core 2 (`prep.c`).
- 60 fps by interpolation (`qgl.c`): the render thread pairs uniform uploads of consecutive frames and plays an intermediate frame at the midpoint; adaptive (falls back to 30 fps when the real frame is too heavy, resumes when it is not).
- Movies: pl_mpeg with NEON decode + a Layer I audio decoder added (the game's movies use MPEG-1 Layer I, which stock pl_mpeg does not support), YUV->RGB565 conversion on a separate thread.
- Read-ahead for the streaming music file (disk reads were 55-100 ms stalls in the forest).
- Start-up error screens: "GAME FILES NOT FOUND" and "SHADER COMPILER MISSING".
- 16:9: the game widens its field of view from the back-buffer size; the Vita renders 640x362 and scales x1.5.

## Bugs found and fixed (useful context)

- **Hardware DXT corrupted on Vita** (speckled lamp/frame textures in game, the intro looked fine). DXT is now decoded on the CPU into 16-bit by default; `SH4_HWDXT=1` re-enables hardware DXT.
- **Vertex-shader translator**: vs.1.1 scalar operands (`rcp`/`rsq`/`exp`/`log`) without a swizzle read `.w`, not `.x`. This broke the animated title background and the 3D camera projection on PC and Vita.
- **DirectInput axis range**: without `EnumObjects`/`DIPROP_RANGE` axes ran 0..65535 so the stick looked permanently pushed (blocked the attract movie).
- **Memory**: host newlib heap shrunk 56 -> 24 MB, vitaGL threshold raised; guest memory now ~166-172 MB, ~4-12 MB of user RAM left for threads (each SDL thread reserves 1 MB of stack; `SH4_SPARE_MB`=12). A shortage made `sceKernelCreateThread` fail and the second movie played without video.
- **Log flushing** to `ux0:` blocked 100+ ms per call -> log is now asynchronous.
- **Synchronous disk reads** on the main thread caused 140-230 ms hitches (`fread` through stdio ~3 MB/s vs `read()` 11-14 MB/s) -> direct reads + read-ahead.
- **Fog** in the translated VS path (`vFog`) and render-target readbacks made lazy.
- The game's logic advances **per loop iteration** (30 Hz), not per delta time, so a 60 Hz loop would double the game speed; hence render/logic decoupling + interpolation.

## 2026-10-24 session (fixes and findings)

- **Textures vanishing / flat gray patches / black frame when interacting with an item or opening Start** (user confirmed fixed): the freeze/pause capture does CopyRects of 512/256/128/4096 render targets into system-memory surfaces; on Vita each one was a `glReadPixels` mid-frame that breaks the vitaGL scene of the FBO being drawn, so what was drawn before was lost. `surf_copy_rects` now skips GPU -> system-memory copies on Vita (`SH4_CPREAD=1` restores).
